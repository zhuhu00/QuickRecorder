# Whisper 最终成片转写

状态：需求已对齐，待实现。

领域术语见项目根目录的 `CONTEXT.md`。

## 产品目标

为 QuickRecorder 自己生成的录音和录屏提供本地多语言最终成片转写，并让用户快速访问可移植的 `.txt` 与 `.srt` 文件。

该功能主要补足“语音备忘录”的两个使用缺口：

- 录制来源不局限于麦克风，还包括 QuickRecorder 捕获的系统声音与耳机播放内容。
- 转写以中文、英文和中英混说为主要场景，不要求用户在不同语言之间反复切换。

第一版仍坚持录制结束后转写，不实现录制期间实时转写。

类似“语音备忘录”的录制库、播放与完整转写阅读体验不进入第一版，后续由 [GitHub Issue #1](https://github.com/zhuhu00/QuickRecorder/issues/1) 跟踪。

## 已确认决策

- 转写对象是最终成片中实际可听见的全部人声，包括系统声音与麦克风的混合结果。
- 转写只在最终成片成功生成后开始，不进行实时转写，也不阻塞下一次录制。
- “录制完成后自动转写”由用户主动开启；首次开启时先告知模型大小并下载模型。
- 取消或失败的录制不触发自动转写；关闭自动转写不自动删除已经下载的模型。
- 第一版锁定 WhisperKit 官方模型 `openai_whisper-large-v3-v20240930_626MB` 与 SpeakerKit Core ML 说话人分离模型，合计约 637 MB；不提供模型切换。
- 模型按需下载，不放入应用安装包；界面展示实际下载大小和进度。
- 模型切换作为可能的后续能力，不进入第一版范围。
- 语言模式提供“自动识别 / 中文 / English”，默认使用“自动识别”。
- “自动识别”覆盖中文、英文和中英混说；强制语言用于降低短录音或单一语言内容的误判。
- 每次成功转写同时生成与最终成片同名的 `.txt` 和 `.srt` 转写伴随文件。
- 转写伴随文件与最终成片保存在同一目录；不嵌入字幕，不修改原始音频或视频。
- 转写使用单任务顺序队列；同一时间只处理一个最终成片，其他项目按成片完成顺序等待。
- 转写队列不阻塞新的录制；录制与转写并行发生时优先保证录制稳定。
- 界面显示当前转写项目以及等待项目数量。
- 转写队列持久化到 Application Support；App 退出、崩溃或重启后，未完成任务从头重新转写。
- 第一版不实现按时间点续跑；原始成片被移动或删除时任务失败且不持续重试。
- `.txt` 和 `.srt` 先写入临时文件，二者全部成功后再提交，避免留下半成品。
- 已完成的转写任务在 App 重启后不会自动重复执行。
- 伴随文件默认与最终成片同名；若目标 `.txt` 或 `.srt` 任一个已经存在，则寻找首个可用的 `-1`、`-2` 等递增后缀。
- `.txt` 和 `.srt` 始终作为一组使用相同后缀，不弹出覆盖确认，也不覆盖现有文件。
- 第一版只转写 QuickRecorder 自己生成的最终成片，不提供任意文件选择或拖拽导入。
- 第一版支持 QuickRecorder 当前输出的音频与视频格式，以及对失败队列任务的手动重试。
- 模型下载中断可继续下载，不占用转写队列的运行位。
- 原始成片不存在、磁盘空间不足或输出目录不可写时直接失败，不自动重试。
- 音轨提取或模型推理等暂时性错误自动重试一次；仍失败时保留任务，等待用户手动重新转写。
- 任何转写失败都不删除或移动原始成片，也不留下半成品伴随文件。
- 转写设置与状态放入现有齿轮展开内容的 `Transcription` 区块，Dock 主面板和 Menu Bar 面板复用同一视图。
- 区块提供自动转写开关、语言、模型下载与删除、当前任务进度、等待数量以及失败任务重试。
- 顶部录制栏保持不变；Menu Bar 图标继续只表达录制状态，不承载转写状态。
- 不新增转写浮动窗口；完成或失败时发送一次系统通知，成功通知可用于定位伴随文件。
- 第一版不在 App 内显示或编辑完整转写，只提供“复制文本”“打开 TXT”和“在 Finder 中显示”等快速访问操作。
- SpeakerKit 自动检测每段录音中的说话人数，并把结果以匿名 `Speaker A / B / C` 标签写入 `.txt`；第一版不识别真实姓名，也不跨录音保存声纹身份。
- `.txt` 按说话人切换输出时间范围、匿名 Speaker 标签和文本；`.srt` 只使用 Whisper 返回的字幕文本与分段时间戳，不包含 Speaker 标签。
- 转写永久采用原语言模式：中文保留中文、英文保留英文，中英混说保持混合。
- 不调用 Whisper 翻译模式，不提供自动翻译或统一输出语言的选项。
- 音轨提取、模型推理和伴随文件生成严格在本地执行；音视频与转写内容永不上传。
- 网络只用于用户明确启用后下载模型；模型安装完成后支持完全离线转写。
- 本地处理失败时不调用 OpenAI API 或任何其他云端服务回退。

该隐私边界记录于 [ADR-0001](../adr/0001-local-only-transcription.md)。

- 模型保存在 QuickRecorder 的 Application Support 目录；界面显示模型名称、实际磁盘占用和删除入口。
- 模型下载或转写进行中时，必须先取消当前操作才能删除模型。
- 删除模型会同步关闭自动转写，但不影响原始成片和已经生成的伴随文件。
- 模型不自动清理；用户再次开启自动转写时重新确认并下载。
- App 退出或崩溃造成的任务中断会在下次启动后从头重试。
- 用户主动取消的任务不会自动恢复；运行中的临时音频和临时字幕会被清理，最终成片不受影响。
- 被取消的任务保留手动“重新转写”入口；取消后队列继续处理下一个项目。
- 转写前使用语音活动检测抑制静音、环境声和纯音乐引发的幻觉文本。
- 最终成片未检测到人声时正常结束，不生成 `.txt` 或 `.srt`，不视为失败，也不自动重试。
- 歌曲歌词识别不属于第一版的主要支持场景。
- 成功任务和“未检测到人声”任务在通知后从队列记录中移除，不长期保存成功历史。
- 失败或用户取消的任务保留在 `Transcription` 区块，提供“重新转写”和“移除”。
- “移除”只删除任务记录，不删除最终成片；录制历史与长期管理留给 GitHub Issue #1。
- 转写完成通知显示最终成片文件名；点击通知直接打开生成的 `.txt`。
- 成功通知提供“复制文本”和“在 Finder 中显示”操作；通知权限关闭时不影响伴随文件生成。

## 开源分发约束

- Argmax OSS Swift 的 WhisperKit、SpeakerKit 与 OpenAI Whisper 代码采用 MIT License。SpeakerKit Core ML 模型仓库当前没有声明 SPDX license，因此模型继续按需下载且不进入 Release ZIP；公开分发前需重新核对其上游模型条款。
- 模型不随 App 安装包分发，因此不会把数百 MB 模型加入 release ZIP。
- 实现时锁定 Argmax OSS Swift 的具体版本，并将该版本、OpenAI Whisper 模型及 Argmax 内含依赖的许可信息加入 `THIRD_PARTY_NOTICES.md`。
- 在依赖版本实际锁定前，不提前填写可能失真的版本号或许可清单。
- 第一版只从 Argmax 官方模型源下载 WhisperKit 与 SpeakerKit 模型，支持完整性校验、断点续传和手动重试。
- 第一版不提供第三方镜像、手动模型导入或安装包内置模型。
- 模型版本与 QuickRecorder 版本绑定，App 不检查或静默升级模型。
- 模型升级只随新的 QuickRecorder 版本提出，并由用户确认下载；新模型验证成功后才删除旧模型。
- 新模型下载或验证失败时继续使用旧模型，不影响已有转写能力。
- 转写队列只持有一个模型实例；队列清空后保留 10 分钟以复用加载结果。
- 队列空闲超过 10 分钟后从内存卸载模型，但保留磁盘模型；新任务到来时自动重新加载。
- 使用电池时仍允许转写，不增加“仅接入电源时运行”设置。
- 转写使用较低后台优先级，新的录制始终优先且不得被转写阻塞。
- macOS 处于严重发热状态时暂缓启动下一个任务，恢复后继续队列；已经开始的转写不主动中断。

## 兼容性约束

- 截至 2026-07-26，Argmax OSS Swift 最新稳定版为 `v1.0.0`；其 Package manifest 声明 macOS 13 / Swift tools 5.10，官方集成文档要求 macOS 14 / Xcode 16。两者都与 QuickRecorder 的 Apple Silicon + macOS 14.2 目标兼容。
- 实际实现并通过构建验证后，才将依赖的精确 revision 写入 `Package.resolved` 和第三方许可清单。
- Argmax OSS Swift 启用严格并发检查；WhisperKit 实例由单一转写服务隔离持有，不跨并发域直接共享。

## 录制链路集成约束

- 只有最终音频或视频完成混音、转码和封装后，才能把最终 URL 加入转写队列。
- 不转写 `.qma`、Writer 输出、中间混音文件或其他临时产物。
- 视频通过 AVFoundation 在本地提取临时音轨，不引入 FFmpeg 可执行文件；任务结束、取消或失败时都清理临时音轨。
- 将任务加入转写队列后立即结束原有录制生命周期；模型加载、音轨提取和推理不得持有 ScreenCaptureKit、相机或麦克风资源。
- 转写模块的错误只更新转写任务状态，不能把已经成功的录制改判为失败。
